# Layer 4: extending and maintaining the pattern language

Joe requested this process layer on 2026-09-12. These three workshop patterns
organize discoveries into proposals, scope review, adoption, and subsequent
maintenance. They are authored process guidance; no runtime gate or sanction
implementation is claimed. They use the workshop family's existing staging
location and do not themselves promote that family into another catalog.

## The sequence

1. [Open Proposals, Named Adoption](open-proposals-named-adoption.flexiarg):
   capture attention at a refusal, resolution, or opportunity; link existing
   guidance; invite affected participants; identify who can adopt the change.
2. [Distinguishing Cases Before Adoption](distinguishing-cases-before-adoption.flexiarg):
   compare a motivating case with a case where applying the response would
   be wrong; review evidence and the meaning of affected cascade edges.
3. [Revise Patterns from Observed Use](revise-patterns-from-observed-use.flexiarg):
   examine application and outcome, propose maintenance, and verify that an
   adopted correction reached authoritative artifacts and their references.

The first pattern opens a proposal; the second informs its adoption decision;
the third returns later observations to the same process. This is a proposed
process sequence, not a claim that a runtime cascade has been registered.

## A small record, extended as the case develops

Start with: source event/artifact, attempted action, tension, observation,
refusal or resolution, reopening condition, and existing pattern/version.
For a change add: owner, affected roles, proposed operation and scope,
contrasting cases, affected cascade relationships, reviewer findings, and
named adoption decision. After use add: application evidence, outcome,
uncertainty, maintenance disposition, and resulting artifact/version.
Missing observations remain explicit; a new candidate is not a new law.

## First instance and scope limits

The apex-institutions review exposed a narrated correction that had not
reached the original table or audit verdict. Its maintenance target is
[Progress Is a Witnessed State Change](progress-is-a-witnessed-state-change.flexiarg),
with the review and repair history in
[the institution draft](../../../../futon2/holes/labs/wm-contract/DRAFT-apex-institutions.md).
The contrasting case is an explicitly unresolved proposal: that is legitimate
without an applied edit, provided it is not reported as a completed correction.
This example motivates the process; it does not establish its effectiveness.

Cooling-off periods and other sanctions are possible future proposals, not
penalties enacted here. The process requires their grounds, authority, scope,
release condition, challenge route, and restoration review to be specified.
The same process applies to amendments of these three patterns.

## Source and local interpretation

[Corneli (2016)](https://metameso.org/~joe/papers/corneli2016institutional.pdf),
sections 3, 5, 7, Example II, and the conclusion, supplies the discussion of
participation in rule revision, formative feedback, shared evaluation cases,
and institutions for building institutions. The refusal-capture trigger,
record fields, admission procedure, and artifact verification above are local
proposals developed with Joe, not claims that the paper specifies them.
