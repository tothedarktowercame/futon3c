## Premise

The corpus stands at ~46% closed (more once batch-2 merges land and are
pushed). The goal is 100%, and that is inevitably reached one problem at
a time. The one pipeline that has demonstrably converted memory-system
activity into a closure (a94A09: obstruction → concept build → callback
→ one-pass close, ~90 min) is case-shaped. So the campaign's unit of
work becomes the CASE: one problem, worked to closure, in whatever order
we pick — **and no case is left until it is closed.**

## The case loop (no park-and-move exit)

1. **Dispatch** with recall (frames: isolated worktree, versioned record,
   receipts both halves).
2. Runner returns a **closure** (→ step 5) or a **precise obstruction**.
3. **Construct**: the obstruction goes through vote→build→callback —
   codex builds the missing lemma/bridge/concept as its own dispatch.
   Construction-ready obstructions are fine; moving on before the
   construction is done is not.
4. **Re-dispatch** with the built concept. Loop to 2.
5. **Close out**: one case report — route, interventions used, memory
   surfaced/used/fingerprinted, honest counterfactual, glue observed,
   and the DEPOSITS written back to the store (proven lemmas, glue,
   obstruction→resolution pair). Merge to master; push; the % ticks.

**Escalation, not skipping:** after ~3 build rounds without closure, the
case escalates to Fable + Joe for a route change — alternative proof
strategy, literature backport (Sobolev-style), statement-level scrutiny,
or Joe's mathematical judgment. The case remains the active case
throughout. The only thing an obstruction can do is change WHO works on
it next, never WHETHER.

## Ordering

Joe holds the pick. Standing recommendation: reuse-maximizing cluster
order — take adjacent problems consecutively so case k's deposits are
case k+1's supply (e.g. the topology cluster once surface-classification
is built, since it gates an 18-problem backlog); lexicographic within a
cluster. First-case recommendation: **polynomial-zero-count-bridge's
voter problem** (3 votes, smallest known build), then a01A12 (best-
understood retrieval case), then the Sobolev backport assessment.

  escalation rulings, merges, ordering proposals.

  between iterations, watchable live via `agent-follow-mode` on the
  runner's REPL buffer.

## Memory-system research, integrated

The memory question rides the cases instead of steering them:

- **Longitudinal metrics** (the residual-capability measure): per-case
  intervention count, reuse events (fingerprinted), one-pass-after-build
  rate, time-to-close — tracked cumulatively; the hypothesis is that
  later cases in a cluster need fewer interventions because earlier
  cases' deposits are in the store.
- **Supply side grows by construction**: every closure deposits; the
  passive-recall channel gets RE-tested (amendment-8 condition) when
  coverage warrants, not re-nulled now.
- **Fingerprint standard unchanged**; USED claims need the artifact.
- **Calibration twins become an audit tool only**: run a blind twin
  when (and only when) a case claims a memory was load-bearing.
