What the memory is about, as it stands today

The futon3c checkout that the live JVM, the Agency and Joe's Emacs all run from carries two stash entries that codex seats left on 2026-09-01 and that nobody has dropped since:

A seat that has just committed a fix and wants to run the new test against the code before the fix reaches for git stash push -- <file>; test; git stash pop. The path is already committed, so the push saves nothing and prints nothing under -q; the pop then applies stash@{0}, the codex entry, to the shared tree. What "useful" means on this page

Not that the memory was retrieved, and not that the reply mentions it. On 09-09 and 09-30 the memory's absence from the seat's context cost a stopped campaign and a hand restore of the live Emacs code. Today the same pop leaves four files with conflict markers. A seat that reaches the memory before testing pre-fix code runs one git show instead, and the stash stack is never touched. The grid shows whether the memory reached; this page shows what reaching it is worth in this one case, dated and quoted.

Where this is thin

  • The 09-09 and 09-30 session transcripts are not on this host; the memory files written within minutes, and for 09-09 the coordinator census, are the records.
  • The two memories prescribe slightly different recipes (overwrite the path in place and check out HEAD after, or write to a temp path and point the test at it). m40 state gives the 09-30 wording as the latest; the store does not list them as a contradiction, and they are not one.
  • The live check is one run per seat.
